# Contributing to WeighIn

WeighIn is a TypeScript Action/measurement CLI with a Rust Soroban simulation
helper. Start with [README](README.md), [architecture](docs/architecture.md),
[evidence](docs/EVIDENCE.md) and [limitations](docs/KNOWN_LIMITATIONS.md).

## Install

Use Node 24 (the GitHub Action runtime) and npm. The checked-in lockfile is the
installation source of truth:

```bash
git clone https://github.com/WeighInNG/WeighIn.git
cd WeighIn
npm ci
```

JavaScript tests do not need Docker or a live RPC. Native replay/integration needs
Linux x64, Rust 1.95.0 and native build prerequisites. Contract integration also
needs `wasm32v1-none`, checksum-verified Stellar CLI 28.1.0 and Docker. Provision
these as shown in [the proof workflow](.github/workflows/flagship-proof.yml).
WeighIn does not install the Rust or Stellar toolchains itself.

## Quality gates

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run bundle
git diff --check
npm audit
```

`lint` checks Prettier formatting in `src` and `test`; `typecheck` checks TypeScript.
`npm test` builds TypeScript, runs Node behavior/evidence tests under `tests`, and
runs Vitest tests under `test`. `npm run test:watch` starts Vitest watch mode.
Use `npm run format` for intentional formatting changes.

The Action executes committed bundles directly. After runtime/dependency changes,
commit both regenerated `bundled/index.js` and `bundled/comment-action.js` with the
source/lockfile. CI independently regenerates them and rejects stale output.
Do not silently relabel earlier evidence as generated by a newer bundle.

## Native replay

```bash
rustup toolchain install 1.95.0
rustup target add wasm32v1-none --toolchain 1.95.0
npm run test:native
cargo +1.95.0 fmt --check --manifest-path native/simulation/Cargo.toml
```

`test:native` builds the real helper and replays saved immutable snapshots (15
native tests at the evidence baseline). This checks snapshot replay, not a new
live-network or clean-build experiment. Rust dependency access and writable build
storage are required. Set `TMPDIR` to healthy owned storage if system temporary
storage is constrained; do not count quota-failed builds as passing evidence.

## Real integration proof

After provisioning the pinned toolchain/sidecar, follow the short
[control/regression/threshold reproduction](docs/EVIDENCE.md#reproduction).
The harness uses real isolated Git revisions, source builds, deployment, RPC,
native meters and bundled Action processes. It never edits the production
reference contract. The strict-threshold command intentionally exits 1; verify
its policy evidence rather than accepting any nonzero exit.

[Repeatability](docs/repeatability.md) separately documents five clean builds and
five live samples per fixture. Network readiness/funding failures, snapshot drift
and provenance mismatches must remain errors, not invented zero measurements.

## Packaging

```bash
npm pack --dry-run --json
```

The package includes JavaScript outputs with TypeScript declarations, both
Action bundles and native helper sources/lockfile. `package.json` `types` points
to `dist/measurement.d.ts`. Mark test-only exports `/** @internal */`; the build's
`stripInternal` omits them from declarations while keeping them in JavaScript.
`tests/type-declarations.test.cjs` packs the tarball and compiles an external
TypeScript consumer against it. It does not include a precompiled helper. A dry run proves
inclusion, not installation or live behavior. Experimental archives are available
in the Git repository. See [dependency review](docs/DEPENDENCY_SECURITY.md) before
upgrading libraries; do not apply forced blanket upgrades.

## Source map

| Path | Responsibility |
|---|---|
| `src/action.ts` | Inputs, HEAD checkout, fetched BASE worktree and orchestration |
| `src/build.ts`, `src/build-selection.ts` | Fixture-selected locked optimized contract builds |
| `src/identity.ts` | Stable logical fixture/contract/case identities |
| `src/account.ts` | Standalone funding and RPC inclusion readiness |
| `src/measurement.ts`, `src/simulation.ts` | Deployment, snapshot capture, resource extraction and parity |
| `native/simulation` | Official native Soroban simulation helper |
| `src/diff.ts`, `src/threshold.ts` | Comparable resource differences and policies |
| `src/comment.ts`, `src/report.ts`, `src/comment-action.ts` | Markdown/artifacts and comment delivery |
| `src/cli.ts` | Prebuilt-WASM measurement JSON command |

## Pull requests

Explain the problem, scoped change, behavior tests, commands/results and unresolved
limitations. Preserve recorded experiment files and producer hashes. Add behavior
coverage for changed functionality. Keep fixtures/interfaces stable when proving
a regression; commit artificial regression code only inside isolated evidence
snapshots. Update product docs when supported behavior or schema semantics change.
