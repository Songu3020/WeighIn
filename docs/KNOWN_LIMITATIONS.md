# Known limitations

These boundaries describe the current implementation. For exact tested values,
see [Evidence](EVIDENCE.md), [metric provenance](metric-provenance.md) and
[architecture](architecture.md).

| Area | Classification | Current boundary and evidence |
|---|---|---|
| Native platform | Unsupported outside tested path | Default helper provisioning is Linux x64 and Rust 1.95.0; `src/simulation.ts` rejects other platforms. A compatible binary override is not proof of another platform. Helper executable identity is bound by SHA256 before, during, across attempts, and before provenance emission |
| Protocol and network | Protocol-dependent / unsupported | Before builds or deployment, the Action requires the standalone network passphrase and protocol 28. Measured transactions must match that network. `rpc-url` is not arbitrary mainnet/testnet support (`src/action.ts`, `src/measurement.ts`, `src/simulation.ts`, `src/account.ts`) |
| CPU / memory | Protocol-dependent | Official native cost-model consumption, not RPC instruction budgets, hardware instructions, RSS, time or fees. Changing helper/calibration invalidates comparison |
| Three metric names | Unavailable | `historical_data_read_bytes`, `contract_data_hard_limit`, `tx_size_bytes` have null consumption/limit and reasons; required policy rules fail, explicit `ignore` opts out |
| Event count limit | Unavailable independent cap | Event count is measured; no independent protocol-28 count cap. A configured policy cap is permitted |
| Historical/archived state | Unsupported | Current-state capture only; archived snapshot entries are rejected by the helper |
| RPC availability | Environment-dependent | Captures must share a ledger/header and agree with native transaction data, return and events. Exactly one matching ledger header row with well-formed history entry XDR is required for the sequence; ambiguous duplicate headers are rejected; the history-entry hash is strictly validated against recomputed SHA-256 of decoded header bytes and response row hash. Every required configuration entry is identified and verified before native execution. Thirty capture attempts bound drift/discovered keys; only the exact observed captive-core 404 RPC error gets three bounded retries. Other errors fail |
| Footprint key validation | Strictly validated | Read-only and read-write footprint keys from both RPC simulation and the native helper must be unique within each list and disjoint across lists; duplicate or overlapping keys are rejected before resource counting or helper execution (`validateFootprintKeys`) |
| State between revisions | Environment-dependent | Snapshots are immutable per invocation, not across the whole suite. BASE/HEAD may use different ledgers. Ledger/time/state changes can change resources even when WASM is unchanged ([controlled ledger-variation proof](ledger-variation.md)). Comparable provenance does not freeze arbitrary state |
| Fixture execution | Unsupported chaining | Each invocation is simulated independently against an immutable RPC-captured ledger snapshot; writes reported by a simulation are discarded. The archived fresh-deployment proof makes this observable: after a constructor commits persistent `bench = 7`, a simulated `bench(2)` deletes it (`modified_entries = 1`), then distinct `bench(0)` asserts `bench == Some(7)` and returns `[7]` from the same ledger. The committed setup distinguishes a discarded delete from initially absent state. Upload/deployment is submitted; only invocations are isolated. Prior invocation output/state cannot be referenced as setup for a later case. Evidence: `tests/native/simulation.test.cjs`, `docs/experiments/metric-provenance/{rpc-captures,native-replays,verification}.json`; an invalid read response fails closed. |
| Authorization / randomness | Not yet validated beyond documented mode | Native replay uses recording auth with testutils/recording_mode and a fixed zero seed. It is not signed production authorization. RPC/native disagreement fails rather than blending resources |
| Source account | Partially validated | The invoking account is recorded in `provenance.source_account` and is compared with the other environment identities, so records measured under different accounts are reported as incompatible. The [source-account proof](source-account-effects.md) covers one contract case on one protocol-28 standalone network: the account changed no measured metric there. Protocol 28 contracts cannot observe the invoker, and recording authorization does not prove that an account satisfies the authorization requirements of a case |
| Fixture arguments | Unsupported outside listed conversions | `toScVal` supports bool, string, symbol, u32/i32, u64/i64/u128/i128, address, hex bytes, typed vec/map. Large integers must be strings. A top-level argument may instead bind a declared dependency's committed setup return (the created contract address), optionally narrowed by `field`/`index` selectors; the selected ScVal must match the declared type and is passed without conversion. Other ScVal types and invocation-output substitution are unsupported ([setup plan proof](setup-plan.md)) |
| Contract builds | Environment-dependent | Default build resolves workspace cdylib target names (falling back to package names when the target name is omitted) from fixture WASM basenames and rejects packages with multiple cdylib targets. Tracked manifests, lockfiles, and contract source inputs are snapshotted and asserted against in-place mutation during the build. Tools, locked dependency access and healthy temporary storage are caller requirements. SDK-specific Rust minimums can exceed the builder's gate |
| WASM artifact preflight | Strictly validated | Every declared fixture WASM is preflighted upfront before account funding or deployment: paths must exist, be regular files, and contain valid WASM binary magic headers (`\0asm\x01\x00\x00\x00`). Multiple errors aggregate with fixture and contract labels. Cross-target fallback (`wasm32-unknown-unknown`) is rejected by default and requires explicit opt-in (`allowCrossTargetSubstitution` / `--allow-cross-target-substitution` / `allow-cross-target-substitution`) |
| Custom / prebuilt builds | Environment-dependent | `build-command` and `skip-build` bypass CLI/version/optimization/fresh-output/storage validation. Callers own artifact freshness and comparable build flags |
| Workspace cleanliness | Required for accurate benchmarking | HEAD workspace must have no modified tracked files before measurement. The Action checks git status and fails if any tracked files are modified, ensuring benchmarks reflect the reported HEAD revision. Untracked files are not part of the compared revision and do not block the run |
| Optimizer storage | Environment-dependent | Pre/post write/fsync/read probes catch the reproduced persistent quota failure. They do not reserve capacity or rule out a transient failure solely during optimization |
| Reproducibility | Not yet validated universally | Five clean reference builds and five samples per seven cases were stable on one controlled host/network. This is not cross-machine/compiler/network or arbitrary-contract determinism. Failed setup attempts are retained |
| Multiple contracts | Partially validated | Structured identities avoid cross-contract collisions; tests and the migration bridge exercise multiple declarations. Identical WASM on one network/deployer can share a runtime address. Contracts may declare `depends_on`; each revision deploys every contract once in validated topological order (declaration order breaks ties), commits all setup before measuring, and aborts the dependents of a failed prerequisite. Constructor arguments and arbitrary setup calls are not supported. Distinct arbitrary stateful multi-contract suites are not validated |
| Cross-contract attribution | Validated within a bounded scope | The [nested invocation proof](nested-invocation.md) charges one top-level transaction for a real caller/callee host call: the combined footprint, charged events and return are attributed per contract, but consumed CPU, memory and bytes are not split per contract |
| Baseline and fixture evolution | Supported with constraints | Action fetches a base ref and uses each revision's fixture contents. Explicit IDs must exist on both sides before moving paths. New/removed cases are reported; at least one case must match. Additions/removals alone have no regression policy |
| Policy scope | Supported with constraints | Per-function rules apply to all logical contracts/cases using that name; no contract/case-specific selectors. No historical trend storage or webhook export exists |
| Historical results | Unsupported mixed-schema comparison | Schema 5 uses approved metric-specific source/cap mappings. Legacy results retain address matching only against legacy; schemas 2/3/4/5 cannot be mixed. Remeasure both revisions |
| CLI | Intentionally limited | Measurement JSON from prebuilt WASM only. Comparison, thresholds and GitHub reporting belong to the Action/API |
| SDK version reporting | Best-effort metadata only | Each contract reports the `soroban-sdk` version of its owning Cargo workspace/lock (`contract/Cargo.lock` or a root workspace `Cargo.lock`), `"unknown"` when unresolved, and multiple declared versions as a comma-separated list. Caller-supplied values are recorded verbatim. It does not prove how a prebuilt WASM was compiled (`docs/record-schema.md`) |
| GitHub comments | Supported with constraints | Separate consumer runs only for successful PR producers, so policy-failure reports remain artifacts/summaries. Direct comment API errors warn without failing an otherwise valid benchmark. Artifacts require retention/auth permissions. Comment upsert scans one comments API response; it does not paginate or disambiguate multiple marker comments (`src/comment.ts`) |
| Report delivery | Atomic replacement, not crash-durable | The Markdown report is written to an owned temporary file in the destination directory and renamed over the destination only after a complete write, so a failed or interrupted write cannot truncate a published report or publish a partial one (`src/report.ts`). The content is not fsynced before the rename, so a host crash can still leave an empty report. The guarantee covers write, rename and cleanup failures, not power loss |
| Endpoint diagnostics | Shape-based redaction only | CLI/Action/transport render a sanitized endpoint: userinfo stripped, query values redacted, fragment dropped, malformed input replaced with `[invalid endpoint]`. Not general-purpose DLP: secrets embedded in the path, response bodies or unrelated text are not guaranteed to be removed. Requests still use the unchanged endpoint |
| External-project coverage | Validated within a bounded scope | [Hosted Soroban Forge proof](hosted-soroban-forge.md) covers the empty participant view in a permitted WeighInNG fork. Funded settlement, populated pagination, deposit/release and upstream adoption are not proven |
